# 模式构建器

`@dsh-plugin/dsh-mode-builder` 为 DSH 提供一个可视化的「模式管理」面板：从标准、极简、PTC、创造或任意已存在的模式派生新模式，勾选要保留的工具与 SKILL，保存后即可在新建会话时选用。

- 面板位于「插件」页的插件详情中，表格列出全部自定义模式，右上角「新增模式」打开向导。
- 向导第一步选择来源模式；选定后立即读取该模式**真实拥有**的工具行与 SKILL，并以复选框展示。
- 工具按容器分组（计划模式、任务委派等），另列「固定保留」行说明不可移除的人设与管线。
- SKILL 以快照方式复制进模式自己的目录，来源技能被移动或删除后模式仍然可用。
- 保存即注册为 Agent 预设，无需重启宿主；新建会话页的模式列表立刻可选。
- 删除模式会同时移除其预设注册与技能快照；已开始的会话保持原有组合。

## 安装

```bash
# 通过插件管理器安装 npm 包（推荐）
dsh plugin --profile web add @dsh-plugin/dsh-mode-builder

# 或从本地仓库安装
dsh plugin --profile web add file:/path/to/dsh-mode-builder
```

插件声明了 `dsh.bundle.patch`，安装后会加入 profile 的 bundle 列表并自动挂载。本插件需要 `@dsh-plugin/dsh-loader` 2.0 与 DSH `0.2.2` 系列。

## 使用步骤

1. 打开「插件」页，进入「模式构建器」详情，展开「模式管理」。
2. 点击右上角「新增模式」。
3. 选择来源模式 → 填写模式 ID 与名称（可选说明）→ 勾选保留的工具 → 勾选携带的 SKILL。
4. 点击「确认添加」。表格即刻显示新行。
5. 切回「新会话」，点击模式胶囊，新模式的名称出现在列表中；选中后开始对话即可。

> 模式在**创建会话时定版**：修改或删除模式不会影响已经开始的会话，这与官方预设定版规则一致。

## 派生规则

| 类别 | 处理方式 |
| --- | --- |
| 固定保留行 | 人设、工作区指令、时间感知、上下文压缩管线、工具执行器与全部斜杠命令原样保留。 |
| 可选工具行 | 勾选即保留，取消勾选即从组合中移除；`!!js` 条件（如按平台选择 Bash / PowerShell）随行保留。 |
| 工具组 | 组只是容器，子行全部移除时整组消失；勾选工作流工具会自动带上 PTC 引擎。 |
| SKILL | 勾选结果写入模式自带的快照目录，`skill-filesystem` 以 `includeDefaultRoots: false` 只扫描该目录；一个都不选时移除技能发现与加载行。 |
| 字面停用行 | 来源里标为 `disabled: true` 的行被勾选后会解除停用，因为「保留」就是对默认停用的覆盖。 |

新增模式的 `order` 取现有最大值 + 1，因此总是排在既有模式之后。

## 数据位置

| 内容 | 路径 |
| --- | --- |
| 模式定义 | `${DSH_HOME}/data/dsh-mode-builder/modes/<id>.json` |
| 技能快照 | `${DSH_HOME}/data/dsh-mode-builder/skills/<id>/<skill>/` |

未设置 `DSH_HOME` 时使用 `~/.dsh`。模式文件自带 `version` 字段便于后续迁移；删除模式会连带删除其技能快照。

## 限制

- 项目级技能（`.dsh/skills`、`.agents/skills`）不参与派生：模式在配置时就已确定，而项目根目录取决于之后打开的工作区。
- 没有本地文件的虚拟技能（例如由运行时注册的技能）无法携带，向导会列出其名称。
- 单个模式最多携带 32 MiB 的技能文件；超限时创建失败并提示。
- 模式 ID 一旦创建不可修改；需要改名时请删除后重新派生。

```bash
npm ci

npm run build       # 生成 lib/index.js 与 lib/client.js
npm test            # 构建 + 派生规则回归测试
```

开发细节见 [配置与操作契约](docs/CONFIG.md)，测试记录见 [验证记录](docs/VERIFICATION.md)。
